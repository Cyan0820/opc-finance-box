# 系统验收与首次上线

## 当前交付形态

这是面向精干游戏团队的本地单用户可运行版，支持中国研发主体与海外发行主体分别核算、管理汇总。这里的“精干”只代表人数少，不假设营收、流水、渠道数量或内控要求低。它不是把大公司 ERP 缩小，而是以业务底稿、异常复核和可审计关账为核心的财务工作台。

已经验收的闭环：

1. 国内/海外游戏结算单→统一台账→勾稽与异常。
2. 采购→验收→发票→付款，含已交付未开票暂估。
3. 银行收付与应收/应付匹配，不同币种独立核对。
4. 工资、累计预扣个税试算和研发人工候选额。
5. 业务台账→凭证草稿→复核→科目试算→利润及资产负债草稿。
6. 月结任务→硬阻塞→负责人关账→锁定→有原因重开。
7. 增值税及附加、A200000企业所得税预缴、A01103印花税税源、个税扣缴和财务报表报送工作底稿，含海外渠道逐渠道复核。
8. 预算实际差异、未来 12 个月现金滚动预测、最低缓冲和跑道预警。
9. 数据持久化、操作审计日志和外部会计复核包。
10. 默认财务目标→主动运行→统一确认队列→交付物证据链；覆盖月结、90 天资金安全和经营变化解释。
11. 多主体资料入口→主体选择/保守建议→人工确认→逐行写入 `entity_id` 与原始资料证据→入账一致性阻断。
12. 应收/应付/工资批次→付款申请或费用报销→统一确认→银行流水核销；管理汇总按币种分列，跨主体与跨币种核销直接阻断，支出核销要求付款授权。
13. 人工关账基准→按主体/期间只读对比→差异解释→独立签认；数据变化后旧签认自动失效。
14. 银行/发票 PDF 或图片→文字识别候选→人工补正并对照原件确认→关键字段阻断→正式台账；合同和验收材料只关联同主体采购，不自动改变验收结论。
15. 首月上线按主体/期间验证每个必需财务域；候选资料不能当正式台账，确实无业务的不适用声明需要复核人、原因和证据，银行、期初及收入不能声明不适用。
16. 收入结算核对底稿可关联同主体结算记录，用于保留经分、平台账单、退款和差异证据，但不会自动改写收入。

## 第一家真实公司建议顺序

1. 在“公司财务档案”填主体、税务属地、纳税人类型、申报周期和外部会计。
2. 导入上期经确认的期末科目余额，只接受借贷平衡的期初。
3. 按法律主体导入渠道结算、采购、发票、银行和工资台账；全球管理汇总中不能仅按币种、国家或渠道猜主体。
4. 配置当期月末汇率，并留下统一、可追溯的汇率来源。
5. 由业务确认验收、渠道履约角色、人员和项目事实；Agent 给出会计/税务倾向和影响。
6. 外部会计或税务机构复核首月收入总额/净额、税务口径和海外渠道证据；形成可复用规则。
7. 接受或退回凭证草稿，确认试算和报表勾稽后再执行关账检查。
8. 下载 Shadow Close 基准模板，导入外部会计已复核结果，逐项解释差异并由独立复核人签认。
9. 导出外部会计复核包，与实际记账及申报结果核对，将经复核的差异回写为规则。

首批 M2G/ROR 真实结算资料的只读结构体检见 [首批真实结算资料结构审计](首批真实结算资料结构审计.md)。该审计证明收入结算样本覆盖，不代表整套月结资料已经齐全。

## 上生产环境前仍需补的工程能力

当前版本可以做单机真实数据试运行，但不建议直接暴露在公网。多用户正式部署前需要：

- 内置服务器默认绑定 `127.0.0.1`；非回环绑定会在缺少至少 32 字符的 `OPC_FINANCE_API_TOKEN` 时拒绝启动。该 Bearer token 只是网络暴露前的最低保护，不替代 TLS、身份系统或职责分离。

- 单点登录、角色权限和职责分离。
- 数据库、事务、版本化迁移、备份和灾备恢复。
- 传输与存储加密、密钥管理、上传文件恶意内容扫描。
- 操作日志的不可篡改存储、监控报警和定期恢复演练。
- 与实际开票、银行、记账和申报系统的受控接口及幂等机制；各属地电子税务局下载模板的版本化适配。

## 验收结果

- 当前自动化测试以仓库 CI 及本地 `python3 -m unittest discover -s tests -q` 的即时结果为准，不在文档中固定历史测试数量。
- HTTP 端到端已验证：首次建立 2026-02 演示目标、主动运行、确认队列、90 天预测、经营洞察、交付物状态及国区 iOS 示例。
- 硬阻塞事项与可确认事项无重叠；有硬阻塞的付款或税务事项不会返回批准动作。
- 交付物区分“已生成、草稿待确认、已完成”，财务报表草稿和税务底稿不会冒充定稿或已申报。
- 标准导入模板：8 个工作表，公式错误扫描为 0，`MODEL STATUS: PASS`。
- 采购结构回归使用运行时生成的虚构工作簿；未提供的验收、发票和付款数据不会被猜测。
- 多主体收件箱回归覆盖：未确认主体不自动识别；币种/渠道不作为主体推断；识别记录主体及原始资料证据不一致时禁止入账。
- 收付款回归覆盖：国服与海外演示均保留付款申请、报销和关键流水的主体归属；海外没有真实发票业务时保持 0 张发票，不为凑齐主体覆盖伪造单据。
- 认证部署下的资金职责分离：operator 可提交付款申请、报销和核销，reviewer 独立处理付款/报销/验收/凭证/税务决定；服务端 actor 绑定登录 principal，资金动作强制幂等键以避免网络重试重复创建。
- Shadow Close 回归覆盖：带标题行的标准 Excel 可往返导入；显式 0 容差不被默认值覆盖；一份基准不能跨主体或跨期间；签认绑定当前对比指纹。
- 非结构化资料回归覆盖：银行 PDF/图片候选保留字段证据且须核原件；关键字段不全禁止提交；合同/验收证据只能关联同主体采购，关联后采购仍保持原验收状态。
- 外部会计复核包的内容和文件数量以当期实际数据及测试结果为准，不固定写死。
- 安全响应头：CSP、`nosniff`、`no-referrer`、禁止嵌入。
