# 前置导入实现说明

## 为什么必须先导主数据

每家公司的对账单和业务台账都不一样，但项目、渠道、组织和供应商的稳定编码是统一财务语义层。若先导交易再补映射，项目收入、人力和采购会各用一套名称，项目损益无法可靠汇总。

## 导入顺序

1. 主体配置：公司、准则、纳税人、申报周期、外部服务机构、现金假设。
2. 游戏项目：项目编码、名称、阶段、负责人、部门、预算单元和成本中心。
3. 渠道规则：渠道编码、项目编码、平台、区域、币种、分成、结算周期和回款天数。
4. 组织映射：匿名人员/岗位编码、部门、预算单元、成本中心、项目、分摊比例和生效月份。
5. 供应商：供应商编码、类别、币种、默认项目和付款天数。
6. 上期期末余额与真实现金。
7. 近12个月结算、采购、银行、发票和工资实际数。
8. 预算/滚动预测和经营KPI。

## 增量与审计

- 主数据按唯一编码更新；经营KPI按月+项目+渠道+区域生成稳定ID。
- 同一记录再次上传会更新，不同ID会追加。
- 已关账期间的经营KPI不能被直接覆盖。
- 每次保存、问答、复核和关账尝试进入审计日志。

## 上线门槛

分析模块最低需要游戏项目、渠道、组织映射和历史结算；完整项目贡献还需要工资与采购。关账底座另外需要主体规则、期初余额和质量检查。经营KPI不是法定财务必需项，但没有它时Agent不能可靠解释收入变化或给投放建议。
