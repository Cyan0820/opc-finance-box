# 香港法团利得税设计包

`jurisdiction.hk` 面向香港法团 OPC，当前成熟度为 `experimental/design`。它把 BRN/UBI、利得税 BIR51、两级税率资格、预缴利得税及申报证据组织成可 fork 的契约，但不计算税额、不判断利润来源地或离岸申索、不生成申报文件，也不连接 IRD 执行提交。

## 官方来源与适用边界

香港税务局说明，香港以商业登记号码 BRN 作为企业和实体的唯一业务识别码 UBI；Pack 因此只保存证书/官方引用和名称匹配结果，不收集完整号码值。[IRD：Unique Business Identifier](https://www.ird.gov.hk/eng/tax/bre_ubi.htm)

IRD 的利得税说明覆盖征税范围、税率与预缴税机制；两级税率 FAQ 同时明确关联实体提名和部分优惠制度等限制。Pack 只把这些变成“需要哪些事实和复核”的证据清单，不从账面利润直接推导应评税利润或税额。[IRD：Profits Tax](https://www.ird.gov.hk/eng/tax/bus_pft.htm)、[IRD：Two-tiered Profits Tax Rates FAQ](https://www.ird.gov.hk/eng/faq/2tr.htm)

BIR51 的实际期限依赖 return 发出、课税年度、税务代表延期和当年电子提交安排。当前 Pack 因此采用 `manual_configuration`，不会仅按财年结束日猜 due date。[IRD：BIR51 Notes and Instructions](https://www.ird.gov.hk/eng/pdf/e51notes.pdf)、[IRD：Electronic Filing of Profits Tax Return](https://www.ird.gov.hk/eng/tax/bus_epf.htm)、[IRD：2025/26 returns issue notice](https://www.ird.gov.hk/eng/ppr/archives/26040102.htm)

## 创建样板

```bash
python3 -m src.cli create examples/box_specs/shopify_stripe_hk.json \
  --output /tmp/hk-opc-box.json

python3 -m src.cli validate examples/boxes/hk_dtc_shopify_stripe_corporation.json
python3 -m src.cli services examples/boxes/hk_dtc_shopify_stripe_corporation.json
```

`tax.hk.registration_profile` 需要实体类型、BRN/UBI 证据引用和利得税/BIR51 范围证据。请求中出现 `brn`、`business_registration_number`、`tax_id` 或 `ubi_number` 会失败关闭。

`tax.hk.evidence_checklist` 检查每条规则的证据 ID、重复项、未知项和官方来源新鲜度。`tax.hk.build_calendar` 只返回 BIR51 与预缴利得税的配置任务，所有 `candidate_due_date` 在有权人填写并批准实际日期前保持 `null`。

## 明确排除

- 利润来源地、离岸申索、常设机构或税收协定结论；
- 应评税利润、亏损、折旧免税额、两级税率资格或税额计算；
- 全球最低税、FSIE、转让定价、国别报告或优惠税制判断；
- 雇主报税、薪俸税、物业税、印花税、商业登记费及海关事项；
- iXBRL/XML、BIR51 或任何其他可提交表单；
- IRD 电子提交、缴款或已申报声明。

上线前必须由香港税务专业人士对具体法团、课税年度、业务来源事实、关联实体和 return 原件完成复核。测试通过不会把本 Pack 升级为 `workpaper` 或 `filing_assist`。
