# 运行时数据升级与恢复

OPC Finance Box 的持久数据不只包含 Pipeline ledger，还包括总账与期间状态、Agent 运行状态、Finance Inbox、公司资料和导入模板。生产部署必须把整个 `OPC_FINANCE_DATA_DIR` 当成一个共同升级与恢复边界。

## 版本化目录

新目录首次启动时会生成权限为 `0600` 的 `runtime-data-manifest.json`，目录本身及受管子目录使用 `0700`。当前 layout v3 包含总账、Agent runtime、Finance Inbox、Pipeline ledger、Connector sync control ledger 和 Release promotion evidence ledger。manifest 记录唯一 layout id、各 store 的路径和 schema 版本，以及不覆盖恢复策略。

systemd 模板在启动 workbench 前显式执行：

```bash
opc-finance-box runtime-data-init /var/lib/opc-finance \
  --actor systemd-workbench-bootstrap
```

空目录可以安全初始化。已有文件但没有 manifest 的旧目录不会被静默接管，必须先停服务、备份并执行预检：

```bash
opc-finance-box runtime-data-inspect /var/lib/opc-finance
opc-finance-box runtime-data-upgrade-preflight /var/lib/opc-finance
opc-finance-box runtime-data-init /var/lib/opc-finance \
  --actor migration-operator \
  --adopt-existing
```

`--adopt-existing` 只建立版本边界并锁定接管时的文件清单指纹，不修改旧业务文件，也不是数据转换。比当前程序更新的 layout 会失败关闭；当前版本不提供自动原地迁移。

layout v1 或 v2 升级到当前 v3 时，必须停止 workbench 与 scheduler，创建并验证匹配当前目录的完整备份，再显式执行：

```bash
opc-finance-box runtime-data-migrate \
  /var/lib/opc-finance \
  /absolute/private/backups/opc-finance-before-v3 \
  --actor migration-operator \
  --service-stopped-confirmed
```

迁移只新增源 layout 缺失的受管 store：v1 新增 `connector_sync` 和 `release_promotion`，v2 只新增 `release_promotion`。它不重写已有业务文件。工具会拒绝与当前 layout id 不匹配或备份后目录已经变化的备份。

## 一致性备份

整目录备份是离线操作。先停止 workbench 和 scheduler，确认没有其他进程写入，再执行：

```bash
opc-finance-box runtime-data-backup \
  /var/lib/opc-finance \
  /absolute/private/backups/opc-finance-2026-08-14 \
  --actor backup-operator \
  --service-stopped-confirmed

opc-finance-box runtime-data-backup-verify \
  /absolute/private/backups/opc-finance-2026-08-14
```

工具在复制前后比较完整文件清单，并在 `runtime-data-backup.json` 中记录每个文件的大小和 SHA-256、总字节数、layout id/version 与 inventory fingerprint。目标目录必须不存在，备份永不覆盖。

备份包含敏感财务数据，工具本身不加密，也不提供数字签名或 WORM 保证。生产环境应使用加密卷、异地复制、访问控制、保留策略和组织级签名/SBOM，并定期做恢复演练。

## 空目标恢复

恢复只允许写入一个尚不存在的新目录：

```bash
opc-finance-box runtime-data-restore \
  /absolute/private/backups/opc-finance-2026-08-14 \
  /var/lib/opc-finance-restored \
  --actor restore-operator
```

工具先重新验证备份，再复制并核对完整清单，最后生成 `runtime-data-restore-receipt.json`。它不覆盖、不合并，不删除旧目录，也不提供 HTTP 恢复接口。完成后先在隔离端口执行 `deployment-smoke` 和只读业务核对，再通过挂载或环境变量切换到新目录；旧目录继续只读保留，直到有权人批准退役。

恢复不能撤销已经发生的银行付款、税务提交或第三方系统动作。这些外部系统必须另行对账。
