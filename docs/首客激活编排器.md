# 首客激活编排器

首客激活编排器把生产准备度的十一道权威门转换成一个依赖感知的操作队列。它不重算税务、不读取私有证据内容，也不执行命令；它只回答三个问题：哪些阶段已经完成、现在可以并行处理哪些阶段、其余阶段被哪些前置证据阻塞。

```bash
opc-finance-box activation-status path/to/box.json \
  --as-of 2026-08-14
```

首次接入真实 OPC 时，先用编译合同中的 `activation-init` 在新的绝对路径创建私有工件目录，按生成的 `commands.json` 从税务适用性持续推进到连续月份与 Pack 晋级，再用 `activation-workspace-status` 读取已经由人完成和签认的真实工件。初始化器不生成通过结论，命令清单中的决定默认失败关闭；详见 [首客私有工作区初始化](首客私有工作区初始化.md)。

跨天或多人接力时，使用 [首客激活 Runbook](首客激活Runbook.md) 记录 `reported-complete`、失败、阻塞或延期。Runbook 的下一步只是操作者恢复提示；`current_wave` 仍只来自生产准备度的权威证据图，两者不会互相冒充。

Workbench 的“财务任务流 → 数据连接器准备”读取同一安全投影：

```text
GET /api/box/activation?as_of=2026-08-14
```

HTTP 不接受私有目录或工件路径。命令行和服务器都复用 `production-readiness` 的权威结果，因此不会出现一套门禁显示阻塞、另一套编排却声称可执行的分叉状态。

## 依赖图

基础契约通过后，主体税务适用性与数据连接器配置可以并行。文件型游戏或平台电商不需要网络 Connector Shadow 时，该阶段自动显示完成；网络型独立站则必须先完成凭证引用，再进入真实并行证据。后续按以下依赖推进：

```text
能力包契约 ──┬─> 税务规则时效 ─> 主体税务适用性 ─┐
              └─> 数据连接器配置 ─> 连接器并行证据 ─┤
                                                     └─> 首家准入
                                                         └─> 资料交接
                                                             └─> 首次试跑登记
                                                                 └─> 首次观察复核
                                                                     └─> 连续月份证据
                                                                         └─> 稳定版晋级
```

每个阶段提供：

- `operator_role`：准备或执行当前工作底稿的稳定角色；
- `independent_review_role`：必须独立完成复核的角色；
- `command_templates`：与当前 CLI 参数合同一致的可复制命令，占位符必须由操作者替换；
- `unmet_dependency_ids`：仍然阻塞当前阶段的前置门；
- `work_status`：`completed`、`ready_to_work` 或 `blocked_by_dependency`。

编排器不会根据命令顺序推断职责分离已经成立。真正写入私有工件时，原验证器仍会重新检查准备人、复核人、登记人和发布人的角色冲突。

## 当前工作波次

`current_wave` 只包含 `ready_to_work` 阶段。典型未接入状态为：

- 文件型游戏或平台电商：先完成逐主体税务适用性；Connector 配置与并行证据为不适用或已完成；
- Shopify + Stripe + Wise 独立站：税务适用性与 Connector 凭证配置可以并行；凭证就绪后才开放 Connector Shadow；
- 多主体 Box：每个主体的税务适用性必须齐全，首家准入和后续观察仍按完整主体集合绑定。

一个阶段证据无效或过期时，只会重新开放该阶段的工作，不会绕过它去开放下游。

## 编译与升级

每个编译 Bundle 的 `production-readiness-plan.json` 都包含十一阶段的 `operator_contract` 和 `first_customer_workspace` 初始化合同：依赖、角色、命令模板、私有目录约束、完整下游私有命令链与禁止伪造项随 Box 一起 fork。`upgrade-check` 会把合同新增视为需要复核，把现有阶段、依赖、角色、命令或初始化合同变化视为 blocking change，防止升级时静默改写首客操作流程。

## 安全边界

响应不返回配置中的私有路径、凭证值、私有工件内容、实际人员、证据引用或财务金额。所有命令都是模板且 `commands_executed=false`。编排状态也不授权数据写入、调度、过账、付款、法定关账、稳定版晋级或外部申报。
