# 分析与QA口径

## 产品定位

分析模块是系统的管理入口。会计运营、税务底稿和外部服务机构协作是执行层，不是产品的全部。

分析模块回答五类管理问题：

1. 哪个游戏/项目创造收入和直接贡献。
2. 人力、外包、投放、技术云和其他采购投向哪里。
3. Actual相对预算/滚动预测偏在哪里。
4. 现金能否覆盖工资、税款、核心服务器和已签采购承诺。
5. 收入变化能否由活跃、付费率、ARPPU、留存和投放效率解释。

## 项目损益口径

- 管理口径收入：渠道或发行对账单中的我方结算金额；不等同于未经会计复核的法定营业收入。
- 项目直接成本：明确归属项目的人力、研发及内容外包、投放、技术云和其他采购。
- 项目直接贡献：管理口径收入减项目直接成本。
- 公司公共/待分配：没有可靠归属的成本保持公共，不用随意比例强行分摊。
- 外币：只有本期配置汇率及来源后才折算；缺汇率的原币记录单独列出。
- 经营KPI：用于解释驱动，不会把运营后台的流水或投放金额重复计入损益。

如果缺少工资或采购台账，Agent仍可给收入方向性排序，但必须降低置信度并明确“项目直接成本不完整”。

## QA回答合同

每条回答包含：所选期间和管理口径、直接回答、Agent判断倾向、置信度、数据证据与来源模块、选项的好处/代价/推荐项、数据缺口和可执行的下一步。

QA不回答法务专业问题。涉及跨境税务时，Agent会给事实判断路径和倾向，但具体申报口径保留给会计/税务服务机构复核，并保留复核结论与证据。

## 知识来源校准

系统结构参考了用户既有游戏公司投后/BP资料中的项目直接利润、经营利润、Actual/Forecast、现金流预测、研发人力、技术服务费、测试/外包和月度管理看板口径；主数据结构参考财务信息化知识库中组织、预算单元、成本中心和项目维度一致性的要求。没有把大公司复杂审批层级原样复制给小团队。
