# 生产准备度总表

生产准备度总表把一个 OPC Finance Box 的分散控制门聚合成同一份只读状态。它不新造税务判断，也不替代现有签认工具；每个阶段仍调用原来的严格验证器，并只投影计数、状态和下一道证据要求。

```bash
opc-finance-box production-readiness path/to/box.json --as-of 2026-08-14
```

Workbench 的“财务任务流 → 数据连接器准备”会读取同一接口：

```text
GET /api/box/production-readiness?as_of=2026-08-14
```

如果需要从状态直接得到当前可执行的角色化工作波次，使用 `activation-status` 或 `GET /api/box/activation`。它只编排本总表已经证明可开始的阶段，不创建第二套 readiness 结论；详见 [首客激活编排器](首客激活编排器.md)。

首次为客户建立私有工件目录时，使用 `activation-init`、`activation-workspace-verify` 和 `activation-workspace-status`。初始化只建立安全目录、未回答底稿和命令合同，不制造任何通过证据；详见 [首客私有工作区初始化](首客私有工作区初始化.md)。

## 十一阶段门禁

| 阶段 | 证明什么 | 不能证明什么 |
|---|---|---|
| 能力包契约 | 当前已选能力包依赖完整，声明能力有实现或运行边界 | 生产成熟、稳定版或真实资料已验证 |
| 税务规则时效 | 官方来源复核尚未过期 | 真实主体适用或登记完成 |
| 主体税务适用性 | 每个主体的适用性签认已受控导入并由独立控制人封印 | 税额正确、税表已提交或税款已支付 |
| 数据连接器配置 | 当前财务任务流使用的数据连接器凭证引用已配置 | 已连接、已完成并行验证或调度已安装 |
| 连接器并行证据 | 私有轮换目录中的真实匿名 schema v2 工件当前、独立复核通过，并覆盖所选网络 Connector Pack | 每个稳定版样本主体/期间已齐全或 Pack 已晋级 |
| 首家试运行准入 | 逐主体资料域、映射和复核计划已批准 | 资料已经交接或质量已经通过 |
| 真实资料交接 | 私有清单与受控接收已签认 | 已导入、已入账或已完成关账 |
| 首次月结试跑登记 | 每个主体的已复核月结运行与交接期间精确绑定 | 结果正确或下一期间获准 |
| 首次观察复核 | 逐主体报告、组合签认和运行台账形成闭环 | 已达到稳定版门槛 |
| 连续月份证据 | 至少两个连续自然月经过独立连续性复核 | 已批准晋级 |
| 稳定版晋级 | 只读验证追加式晋级账本，并要求当前 Box 下每个未达 stable 的已选 Pack 都有当前版本的最新独立批准 | Pack manifest 已修改、过账、付款、法定关账或外部申报授权 |

总表的 `gate_passed` 表示可以进入该阶段的下一道控制；`evidence_complete` 表示该阶段的证据本身完整。两者故意分开。例如网络数据连接器凭证齐全时，配置门可以通过，但在真实有界并行验证和财务勾稽完成前，`evidence_complete` 仍为 `false`。

## 私有工件配置

命令行和服务器只从受控环境读取私有路径，不接受 HTTP 查询参数覆盖，也不会把路径、执行人、理由、证据引用、账号、税号、凭证或金额放进响应：

- `OPC_TAX_APPLICABILITY_REVIEW_DIR`
- `OPC_TAX_APPLICABILITY_REGISTRY_RECEIPT`
- `OPC_CONNECTOR_SHADOW_REVIEW_DIR`
- `OPC_PILOT_READINESS_REVIEW`
- `OPC_PILOT_DATA_HANDOFF_REVIEW`
- `OPC_PILOT_SHADOW_RUN_REGISTRATION`
- `OPC_PILOT_SHADOW_OBSERVATION_REVIEW`
- `OPC_PILOT_SHADOW_ENTITY_REPORT_DIR`
- `OPC_PILOT_SHADOW_PORTFOLIO_REVIEW`
- `OPC_PILOT_SHADOW_SERIES_REVIEW`
- `OPC_PILOT_SHADOW_SERIES_EVIDENCE_ROOT`
- `OPC_STABLE_PROMOTION_ROOT`

Pipeline 运行台账由 CLI 的 `--runs-root` 或服务器当前运行数据目录提供。`OPC_STABLE_PROMOTION_ROOT` 必须是绝对、非符号链接的 `0700` 目录，且只含非硬链接、`0600` 的 hash-chain ledger 与 lock；Workbench 用共享文件锁只读检查，不创建目录、lock 或事件。缺路径、额外文件、权限过宽、链损坏、Box 指纹变化、Pack 版本变化、待复核/驳回、主体缺失、规则过期、职责重叠或连续月份断裂都会保持失败关闭。

最后阶段按 Pack 独立计算：只批准一个 Pack 会显示 `partial_or_pending_pack_promotion`，只有当前 Box 所选的全部非 stable Pack 都有当前版本的最新 `stable_candidate_approved`，`ready_for_stable_promotion` 才为 `true`。它只是“源码状态变更所需证据已齐”的安全投影；`readiness_is_release_approval` 和 `stable_promotion_performed` 仍固定为 `false`。

## 编译交付

每个编译 Bundle 包含 `production-readiness-plan.json`。它固定当前 Box 的主体、已选能力包、地区规则复核窗口、数据连接器证据要求、十一阶段顺序、每个阶段的依赖/角色/命令模板，以及首客私有工作区初始化合同，但不读取运行环境或私有证据，因此编译结果仍可复现。Connector Shadow 私有目录的操作契约见 [Connector Shadow 证据登记](ConnectorShadow证据登记.md)。

运行时总表永远保持以下边界：

- `ready_for_stable_promotion` 只在只读晋级账本证明全部目标 Pack 已独立批准时为 true，但仍不修改 Pack manifest；
- `ready_for_external_filing=false`，外部申报必须按国家、税种、登记、表单版本和外部系统另行批准；
- 不执行数据连接、调度、过账、付款、关账、申报或任何外部动作。
